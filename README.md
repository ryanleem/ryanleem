## About Me

I'm a **Data Science student at UCLA** and I spend a lot of my time building projects around problems I run into or topics I want to understand better.

I originally got into programming through game development, but over time I started getting more interested in **data science, backend development, machine learning, databases, and software engineering**.

That has led me to work on things like a GitHub bug search engine, fraud analysis on a million bank applications, automated banking reports, e-commerce analytics, computer vision, and game systems.

Right now I'm especially interested in **data science, software engineering, machine learning, and quantitative finance**.

## Featured Projects

<details>
<summary><strong>GitHub Bug Finder</strong></summary>

<br/>

I built this because searching through GitHub issues for a problem you've already seen before can be surprisingly annoying.

Instead of only matching exact keywords, the project uses semantic search to find bug reports that are actually related to what you searched.

| | |
|:---|:---|
| **Stack** | Python · FastAPI · PostgreSQL · pgvector · Sentence Transformers |
| **Scale** | 11,336 indexed GitHub bug reports |
| **Search** | Embedding-based similarity search + live GitHub issue search |
| **Repository** | [github-bug-finder](https://github.com/ryanleem/github-bug-finder) |

The part I liked most about this project was that it went beyond just analyzing a dataset. I had to build the database, API, search logic, embeddings, and frontend together into something that could actually be used.

</details>

<br/>

<details>
<summary><strong>Bank Account Fraud Risk Analytics</strong></summary>

<br/>

I wanted to see how much useful fraud information I could pull from a large dataset using SQL before immediately jumping into machine learning.

| | |
|:---|:---|
| **Stack** | PostgreSQL · SQL |
| **Scale** | 1,000,000 bank account applications |
| **Fraud Cases** | 11,029 |
| **Analysis** | Payment behavior · credit risk · multi-factor combinations |
| **Repository** | [bank-account-fraud-risk-analytics](https://github.com/ryanleem/bank-account-fraud-risk-analytics) |

One of the strongest patterns I found was that applicants with a credit risk score above 178 and payment type AC were much more likely to be fraudulent.

That rule identified **2,084 fraud cases**, or about **18.9% of all fraud in the dataset**.

</details>
